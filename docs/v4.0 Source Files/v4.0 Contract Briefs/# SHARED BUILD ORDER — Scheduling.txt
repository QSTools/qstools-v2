# SHARED BUILD ORDER — Scheduling / Gantt + Staff Time Portal

## Phase 1 — Keep Modules Separate

Build Scheduling and Staff Time as separate modules.

Scheduling route:

app/scheduling/page.tsx

Staff Time route:

app/staff-time/page.jsx

Do not merge the staff portal into the Gantt page.

Do not expose owner/admin Gantt data to staff.

## Phase 2 — Add Shared IDs

Scheduling must preserve:

- job_id
- schedule_id
- task_id

Staff Time must store:

- job_id
- schedule_id
- task_id
- time_entry_id

Photo evidence must store:

- job_id
- schedule_id
- task_id
- time_entry_id

## Phase 3 — Staff Time Task Selector

Staff Time should eventually allow staff to select a scheduled task.

Task selector consumes a staff-safe schedule task list.

No costs, recovery, rates, margins, or claim values.

## Phase 4 — Daily Site Note Shell

Create the Daily Site Note contract.

Do not overbuild the UI yet.

Store enough data to link:

- job
- task
- date
- time entries
- notes
- photos
- delay flags
- variation flags

## Phase 5 — Gantt Click-To-Open

Scheduling / Gantt should allow click on task/date to open the Daily Site Note.

If it exists, open it.

If it does not exist, create/open a draft.

## Phase 6 — Gantt Evidence Markers

Add markers to the Gantt for:

- time logged
- note exists
- photo exists
- delay exists
- variation exists
- review required

## Phase 7 — Admin Review

Owner/admin can review Staff Time evidence inside Scheduling.

Accepted impacts create:

- schedule change log
- delay record
- client notice draft if required

Rejected impacts remain as site evidence only.

## Phase 8 — Future Claim Support

Daily Site Notes feed:

- monthly claim review
- variation evidence
- delay evidence
- work completed records
- labour actuals
- claim pack generator
