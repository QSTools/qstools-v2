# SHARED CONTRACT — Daily Site Note

## 1. Purpose

Daily Site Note is the shared record between Scheduling / Gantt and Staff Time Portal.

It records what actually happened on a job, task, and date.

It becomes the bridge between:

- planned programme
- staff time entries
- daily site notes
- photo evidence
- delay records
- variation evidence
- monthly claims
- client notices
- job history

## 2. Ownership

Daily Site Note is created from either:

- Staff Time Portal
- Scheduling / Gantt
- Admin entry
- Import

It must be viewable from the owner/admin Scheduling / Gantt module.

Staff should only see or submit their own allowed capture records.

## 3. Identity Fields

Daily Site Note fields:

- daily_site_note_id
- entry_date
- job_id
- schedule_id
- task_id

## 4. Planned Context Fields

These fields come from Scheduling / Gantt:

- planned_description
- planned_start_date
- planned_end_date
- row_type
- team
- role
- contract_scope_type
- contract_item_id
- variation_order_id

## 5. Actual Site Fields

These fields come from Staff Time and/or admin entry:

- actual_work_completed
- daily_notes
- delay_reason
- variation_flag
- variation_description
- site_instruction_reference
- weather_note
- access_note
- safety_note
- material_note
- subcontractor_note

## 6. Linked Records

Daily Site Note should link to:

- time_entry_ids[]
- photo_evidence_ids[]
- delay_record_ids[]
- client_notice_ids[]
- workorder_ids[]
- purchase_order_ids[]

## 7. Review Fields

Review fields:

- created_from
- created_at
- updated_at
- submitted_by
- reviewed_by
- reviewed_at
- review_status

Allowed created_from values:

- staff_time
- gantt
- admin_entry
- import

Allowed review_status values:

- draft
- submitted
- reviewed
- approved
- requires_follow_up

## 8. Schedule Impact Fields

Daily Site Note may flag possible schedule impact:

- schedule_impact_flag
- schedule_impact_reason
- suggested_new_start_date
- suggested_new_end_date
- suggested_work_days_change
- admin_action_required

Important rule:

Daily Site Note may suggest schedule impact.

It must not directly overwrite the schedule.

## 9. Claim / Evidence Fields

Daily Site Note may support monthly claims and evidence.

Fields:

- claim_relevance
- claim_status
- evidence_complete
- evidence_notes

Allowed claim_relevance values:

- none
- contract_progress
- variation
- delay
- daywork
- rework
- review_required

Allowed claim_status values:

- not_claimable
- potential_claim
- claim_pending
- submitted
- approved
- rejected
- disputed

## 10. Final Definition

Daily Site Note is the daily job/task/date evidence record.

Scheduling / Gantt uses it to show actual site evidence against the planned programme.

Staff Time Portal uses it to submit time, notes, variation details, delay notes, and photo evidence.

Monthly claims and job history later use it as the evidence base.
