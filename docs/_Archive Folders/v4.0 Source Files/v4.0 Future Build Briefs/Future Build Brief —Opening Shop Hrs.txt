# QS Tools — Implementation Brief

## Shop Opening Hours / Business Trading Hours Layer

## 1. Purpose

The Shop Opening Hours layer defines when the business is open and available to trade.

It is not a labour cost module, not a recovery module, and not a pricing module.

Its purpose is to answer:

```txt
When is the business open?
How many trading hours exist per week?
How many trading days exist per week?
How many annual trading hours are available?
How does this compare to productive labour capacity later?
```

This becomes important for businesses such as:

```txt
retail shops
cafes
restaurants
salons
workshops
service counters
showrooms
clinics
hire businesses
```

## 2. System Role

Shop Opening Hours is a **business availability input layer**.

It should sit upstream of later business modelling and recovery interpretation.

Suggested position:

```txt
Business Setup
↓
Shop Opening Hours
↓
Labour
↓
Cost Summary
↓
Recovery Summary
↓
Cost Allocation
↓
Recovery Outcome
```

It defines business trading availability, not staff productivity.

## 3. Core Distinction

Do not confuse:

```txt
Shop opening hours = when the business can trade
Labour hours = when staff are paid / productive
Productive hours = usable labour output
Recovery hours = hours used to recover business cost
```

Example:

```txt
Shop open: 50 hours/week
Staff paid: 120 hours/week total
Productive labour: 95 hours/week
```

These are related but not the same thing.

## 4. Module Ownership

Shop Opening Hours owns:

```txt
opening profile
days open
open / close time per day
weekly trading hours
annual trading hours
public holiday / closed-day assumptions
```

It does not own:

```txt
staff_id
labour cost
asset cost
general overheads
recovery strategy
operating groups
pricing
sales forecasts
```

## 7. Calculations

### Daily Trading Hours

```txt
daily_trading_hours =
(close_time - open_time) - break_minutes
```

If the day is closed:

```txt
daily_trading_hours = 0
```

### Weekly Trading Hours

```txt
weekly_trading_hours =
sum(daily_trading_hours for all open days)
```

### Weekly Trading Days

```txt
weekly_trading_days =
count(days where is_open = true)
```

### Annual Trading Hours Before Closures

```txt
annual_trading_hours_before_closures =
weekly_trading_hours × trading_weeks_per_year
```

### Average Daily Trading Hours

```txt
average_daily_trading_hours =
weekly_trading_hours / weekly_trading_days
```

If weekly_trading_days is zero:

```txt
average_daily_trading_hours = 0
```

### Closure Hours

```txt
closure_hours =
(closed_public_holiday_days + planned_closed_days)
× average_daily_trading_hours
```

### Net Annual Trading Hours

```txt
net_annual_trading_hours =
annual_trading_hours_before_closures - closure_hours
```

Never allow negative output:

```txt
net_annual_trading_hours = max(0, calculated value)
```


## 9. Status / Warning Rules

Warnings:

```txt
no_open_days
invalid_open_close_time
close_time_before_open_time
zero_weekly_trading_hours
high_closure_days
profile_not_saved
```

Readiness:

```txt
is_opening_profile_ready = true when:
- at least one day is open
- weekly_trading_hours > 0
- all open days have valid open and close times
- net_annual_trading_hours > 0
```

## 11. Important UX Rule

Use normal business language.

Do not call this:

```txt
capacity model
availability engine
trading abstraction
```

Use:

```txt
Shop opening hours
Trading hours
Days open
Closed days
Annual opening hours
```

## 12. Downstream Use

This layer can later support:

```txt
Revenue Reality
Revenue Summary
Recovery Outcome
Business Outcome
shop-based recovery models
sales per trading hour
labour coverage vs opening hours
minimum staff coverage checks
```

But V1 should only expose opening hours cleanly.

Do not force downstream integration in the first build.

## 13. Future Comparison Logic

Later, the system can compare:

```txt
net_annual_trading_hours
vs
productive_labour_hours
```

Useful warnings later:

```txt
shop_open_more_hours_than_labour_can_cover
labour_capacity_exceeds_opening_hours
weekend_trade_without_weekend_labour
evening_trade_without_staff_cover
```

These should not be built in V1 unless the Labour contract is already ready to support it.

## 14. Not Allowed

Do not:

```txt
calculate wages here
calculate recovery rates here
assign staff here
create staff_id here
calculate pricing here
duplicate Labour productive hours
duplicate Cost Summary recovery
hide formulas in components
use page.jsx for calculations
```

```txt

```

```txt
correct weekly trading hours
weekend_open = true
```

## 18. Final Definition

Shop Opening Hours is a business availability input layer that defines when the business is open to trade, calculates weekly and annual trading hours, and provides a clean output contract for later revenue, labour coverage, and recovery analysis without owning labour cost, recovery, pricing, or operating group logic.
