## Key findings

### 1. Assets readiness is too narrow

Right now:

```text
assets_ready = reconciliation_state === "green"
```

That means Assets can only pass if there is an asset benchmark and the variance is tiny.

But our v3.6 rule requires a second valid path:

```text
No active assets
+ user explicitly confirms no active assets
+ asset cost = 0
= Assets ready
```

That path does not exist yet.

### 2. `no_active_assets_confirmed` is missing

Codex found:

```text
no_active_assets_confirmed: no occurrences
```

So this needs to be added to:

```text
asset storage
asset hook/output contract
asset calculations
asset UI
reconciliation check
```

### 3. Paid-off finance is not handled yet

Current finance calculation still appears to calculate finance cost from:

```text
purchase_price
interest_rate
finance_term_years
```

But it does **not yet check whether the finance term has ended**.

So this rule still needs implementing:

```text
If purchase date + finance term is before the current model period/date,
current finance cost = 0
```

That is separate from `no_active_assets_confirmed`.

### 4. P&L asset finance exclusion is conceptually correct

The P&L can exclude asset finance interest using:

```text
interest_treatment === "asset_finance_exclude"
```

That is correct because Assets owns asset finance/ownership cost.

So we should **not** change P&L for this next fix.
