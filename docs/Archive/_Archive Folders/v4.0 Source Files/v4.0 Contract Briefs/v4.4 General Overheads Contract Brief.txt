Mirra v4.0 — General Overheads Contract Brief# Mirra v4.0 — General Overheads Contract Brief

## Status

Implemented / current working contract.

This brief records the agreed General Overheads contract after the v4.0 cleanup of overhead redistribution pools, asset-related overhead flow, and downstream Cost Summary / Assets behaviour.

---

## 1. Purpose

General Overheads is a source and review module.

It consumes operating expense costs from the P&L and prepares them for downstream use without changing the original P&L source totals.

General Overheads is responsible for:

* reviewing overhead costs
* grouping overhead costs into stable Mirra buckets
* redistributing selected broad P&L pools into useful modelling buckets
* exposing asset-related overhead pools to the Assets module
* preserving the fixed General Overheads total for Cost Summary and Business Summary
* maintaining traceability back to P&L source values

General Overheads does not perform final recovery, pricing, rate building, or business outcome diagnosis.

---

## 2. Core Contract Rule

General Overheads may redistribute costs, but it must not create new cost.

For each redistributed pool:

```txt
Manual assigned portions
+ auto-balanced remaining portion
= original P&L source pool total
```

The original source amount remains locked to the P&L.

Redistribution changes how the cost is used downstream. It does not change the accounting source total.

---

## 3. Source Flow

The intended flow is:

```txt
P&L
→ General Overheads
→ asset-related overhead pools
→ Assets
→ Cost Summary
→ Business Summary
→ Cost Allocation
→ Recovery Summary
→ Rate Builder
```

General Overheads consumes P&L operating expense lines.

The P&L remains the source of truth for operating expense totals.

General Overheads is the review layer where broad overhead pools are split into business overhead and asset-related pools.

---

## 4. Fixed General Overheads Total

Cost Summary must consume the fixed General Overheads total.

Cost Summary must not add redistribution rows as extra overhead cost.

Cost Summary must not consume asset-related pools as duplicate overhead cost.

The General Overheads top-line total remains the P&L-derived overhead burden.

Asset-related pools are downstream-use pools, not new cost.

---

## 5. Redistribution Pools Implemented

The following redistribution pools are implemented.

---

## 5.1 Vehicle Running Costs

Vehicle Running Costs is a P&L-derived source pool.

It is redistributed into:

```txt
Fuel — manual
Repairs / Maintenance — manual
Registration / Compliance — auto-balance
```

Contract rule:

```txt
Fuel
+ Repairs / Maintenance
+ Registration / Compliance
= Vehicle Running Costs P&L source pool
```

Fuel flows to:

```txt
asset_fuel_pool
```

Repairs / Maintenance flows to:

```txt
asset_repairs_maintenance_pool
```

Registration / Compliance flows to:

```txt
asset_registration_compliance_pool
```

The row order must remain fixed:

```txt
1. Fuel
2. Repairs / Maintenance
3. Registration / Compliance
```

Rows must not reorder by amount while the user is typing.

Tyres / Consumables was intentionally removed from the Vehicle Running Costs redistribution UI for the current contract.

---

## 5.2 Insurance / Compliance

Insurance / Compliance is a P&L-derived source pool.

It is redistributed into:

```txt
Business Insurance — manual
Vehicle / Asset Insurance — manual
Professional Indemnity — manual
Compliance / H&S — auto-balance
```

Contract rule:

```txt
Business Insurance
+ Vehicle / Asset Insurance
+ Professional Indemnity
+ Compliance / H&S
= Insurance / Compliance P&L source pool
```

Vehicle / Asset Insurance flows to:

```txt
asset_insurance_pool
```

Business Insurance, Professional Indemnity, and Compliance / H&S remain business overhead unless deliberately changed in a future contract.

Compliance / H&S is the auto-balance row.

---

## 5.3 Finance / Interest

Finance / Interest is a sensitive pool.

It must remain conservative by default.

The user-facing question is:

```txt
Does Finance / Interest include asset finance?
```

It is redistributed into:

```txt
Includes Asset Finance Portion — manual
No Asset Finance / Business Finance Balance — auto-balance
```

Contract rule:

```txt
Includes Asset Finance Portion
+ No Asset Finance / Business Finance Balance
= Finance / Interest P&L source pool
```

Only the manually entered asset finance portion flows to:

```txt
asset_finance_interest_pool
```

The balance remains in General Overheads as business finance overhead.

Important rule:

```txt
Do not automatically move all Finance / Interest into Assets.
```

Asset finance must be explicitly entered.

This protects the model from incorrectly treating bank fees, overdraft interest, or general business finance as asset finance.

---

## 6. Asset-Related Pool Outputs

General Overheads exposes the following asset-related pools:

```txt
asset_fuel_pool
asset_insurance_pool
asset_repairs_maintenance_pool
asset_registration_compliance_pool
asset_consumables_pool
asset_finance_interest_pool
```

These pools are consumed by the Assets module.

Assets assigns these pools to individual assets.

Assigned asset-related overheads are included in asset recovery calculations.

---

## 7. Assets Module Contract

Assets consumes only the asset-related pools exposed by General Overheads.

The Assets module is responsible for:

* showing available pool amount
* showing assigned amount to the current asset
* showing assigned amount to other assets
* showing remaining pool amount
* limiting assignment to the maximum available for the current asset
* warning if a pool is over-allocated
* including assigned overhead pool amounts in asset recovery cost

Assets must not recreate General Overheads logic.

Assets must not alter the General Overheads source pool.

Assets assigns available pools to assets.

---

## 8. Cost Summary Contract

Cost Summary must consume the fixed General Overheads total only.

Redistribution rows must not be counted as extra costs.

Asset-related pools must not be added again as additional overhead.

Cost Summary must avoid double counting where asset-related overhead is assigned to assets.

The intended behaviour is:

```txt
General Overheads source total remains stable.
Asset-related portions are exposed for asset assignment.
Cost Summary continues to use the correct fixed overhead basis.
```

---

## 9. Warning / Guardrail Contract

General Overheads and Assets should provide clear warning states for:

```txt
over-assigned pool
partially assigned pool
unallocated / needs review rows
asset pool over-allocation
```

General Overheads should warn when a redistributed pool exceeds its P&L source total.

Assets should warn when asset pool assignments exceed the available pool amount.

Assets readiness should be blocked or reviewed when asset overhead pools are over-allocated.

---

## 10. UI Contract

General Overheads reclassification UI should show redistribution rows clearly.

The user should not see confusing duplicate source/helper rows for the controlled pools:

```txt
Vehicle Running Costs
Insurance / Compliance
Finance / Interest
```

For Vehicle Running Costs, the UI should show:

```txt
Fuel
Repairs / Maintenance
Registration / Compliance
```

For Insurance / Compliance, the UI should show:

```txt
Business Insurance
Vehicle / Asset Insurance
Professional Indemnity
Compliance / H&S
```

For Finance / Interest, the UI should show:

```txt
Includes Asset Finance Portion
No Asset Finance / Business Finance Balance
```

Auto-balance rows should be clearly understood as calculated balances.

Manual rows are user-entered redistribution amounts.

---

## 11. Rounding Contract

General Overheads allocation override amounts should be rounded to two decimals when saved.

This prevents long floating point values from entering saved state.

Expected saved precision:

```txt
2 decimal places
```

This applies to:

```txt
system_allocation_amount_overrides
```

---

## 12. Selector Structure Contract

The old large General Overheads selector file was split into smaller selector files.

Public entry point remains:

```txt
lib/selectors/generalOverheadSelectors.js
```

Internal selector folder:

```txt
lib/selectors/general-overheads/
```

Expected files:

```txt
generalOverheadAllocationSelectors.js
generalOverheadCardSelector.js
generalOverheadCategorySelectors.js
generalOverheadDefinitions.js
generalOverheadFormatting.js
generalOverheadPoolSelectors.js
generalOverheadWarnings.js
```

The purpose of the split is to keep future changes config-driven and avoid large selector rewrites.

---

## 13. Do Not Break Rules

Future changes must not:

```txt
change P&L source totals
create new cost during redistribution
double count asset-related overheads
move all Finance / Interest into Assets by default
hide the remaining business balance
make auto-balance rows behave like independent source costs
make Cost Summary consume redistribution rows as extra overhead
make Assets recreate General Overheads logic
remove traceability back to P&L source pools
```

