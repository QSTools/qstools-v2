# QS Tools — Cost Allocation Implementation Brief

## Work Completed in Current Chat

## 1. Major Direction Change

Cost Allocation was changed from a multi-tab assignment model into a **group-first operating model**.

Previous confusing flow:

```txt
Allocation profile
Operating groups
Capability links
Labour assignment
Asset assignment
Overhead distribution
Checks
```

New intended flow:

```txt
Operating groups
→ labour / assets / overhead inside each group
→ checks
```

The user should build each operating group in one place.

## 2. Allocation Profile Removed from Visible Flow

The Allocation Profile concept was considered confusing and unnecessary for the current default build.

Decision:

```txt
Allocation profile is not where users test scenarios.
Default/current setup is assumed.
Scenario testing belongs later.
```

The visible user flow now starts with **Operating groups**.

## 3. Operating Groups Became the Main Builder

Operating groups now represent real working units, such as:

```txt
Site Labour
Pump Crew
Install Crew
Total Crew
```

Each operating group contains:

```txt
Group name
Group cost summary
Productive labour group / crew
Productive assets
Automatic overhead
```

## 4. Labour Assignment Fixed

### Before

Labour assignment was awkward and appeared to use individual staff or unclear productive/non-productive concepts.

### After

Labour assignment uses productive staff type / labour group from the Labour module.

Example:

```txt
Site Crew
Junior / Trainee
site_foreman
```

The user assigns a whole-number percentage.

Example:

```txt
Site Crew → 100%
```

### Capacity Guard Added

Each labour group can only be used up to 100% total across all operating groups.

The UI now:

```txt
shows remaining %
caps input to remaining %
disables fully allocated labour groups
shows "fully allocated"
```

## 5. Labour Assignment Display Fixed

A wiring issue appeared where assigned labour rows showed:

```txt
Old / unmatched labour group — remove and re-add
0 productive hrs
$0
```

This was caused by display logic checking assigned values instead of resolving saved `staff_type_id` back to the active Labour module rows.

Fix added:

```txt
resolve saved assignment ID
find matching labour row
derive display name
derive assigned hours
derive assigned cost
only show old/unmatched if no source row matches
```

Current confirmed behaviour:

```txt
Site Crew resolves correctly
Junior / Trainee resolves correctly
site_foreman resolves correctly
hours and costs display correctly
```

## 6. Asset Assignment Fixed

Assets were given the same capacity guard as labour.

Each productive asset can only be assigned up to 100% total across all operating groups.

The UI now:

```txt
shows remaining %
caps input to remaining %
disables fully allocated assets
shows "fully allocated"
```

### Asset Display Fix

Asset assignment had the same display issue as labour.

Rows showed:

```txt
Productive asset
100% · $0
```

Fix direction added:

```txt
resolve saved asset_id back to active asset row
display real asset name
derive assigned asset cost from asset source row if stored assigned cost is missing
show old/unmatched only if no matching asset row exists
```

## 7. Overhead Assignment Simplified

Manual overhead assignment was removed from the default group builder.

Reason:

```txt
Labour = capacity, assigned manually
Assets = capacity, assigned manually
Overhead = burden, distributed automatically
```

### New Overhead Rule

Overhead auto-distributes by:

```txt
1. Labour cost weighted
2. Asset burden weighted
3. Equal split fallback
```

Implemented in:

```txt
lib/calculations/costAllocationRules.js
```

The UI now shows overhead as read-only:

```txt
Automatic overhead distribution
% split
$ amount
method
```
