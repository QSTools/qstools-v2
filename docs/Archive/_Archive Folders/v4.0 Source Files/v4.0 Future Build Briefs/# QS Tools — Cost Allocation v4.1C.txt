# QS Tools — Cost Allocation v4.0 Contract Brief

## Division + Operating Groups Model

## 1. Purpose

Cost Allocation defines the operating structure of the business.

It answers:

```txt
Which divisions exist?
Which operating groups belong to each division?
Which productive labour groups are assigned to each operating group?
Which productive assets are assigned to each operating group?
How is overhead automatically distributed?
Is the business operating structure complete enough to support the recovery strategy?
```

Cost Allocation does not calculate prices, set recovery rates, or decide whether the business should proceed. Those remain downstream responsibilities.

## 2. Core System Position

```txt
Cost Summary
↓
Recovery Summary
↓
Cost Allocation
↓
Recovery Outcome
```

The separation remains:

```txt
Cost Summary = WHAT it costs
Recovery Summary = HOW it is recovered
Cost Allocation = HOW the business is structured to deliver it
Recovery Outcome = SHOULD you run it
```

## 3. Locked Model

Cost Allocation v4.0 is now:

```txt
Division
↓
Operating Group
↓
Productive Labour Groups
Productive Assets
Automatic Overhead
```

This replaces the old visible link-first model.

## 4. Deprecated Active Flow

The following concepts are no longer part of the active visible Cost Allocation flow:

```txt
Capability Links
asset_labour_links as the main structure
linked_staff_count as the main coverage metric
linked_asset_count as the main coverage metric
unlinked_staff_count as the main problem metric
unlinked_asset_count as the main problem metric
```

These may remain temporarily for backwards compatibility, but they must not drive:

```txt
structure_valid
coverage
warnings
side cards
setup checklist
Recovery Outcome
```

## 5. Division Definition

A Division is a high-level operating area of the business.

Examples:

```txt
Concrete Pumping
Placing Crew
Workshop
Retail Shop
Front of House
Kitchen
Delivery
Admin Support
```

A Division groups one or more operating groups.

A Division is not a pricing package and not a recovery model.

## 6. Operating Group Definition

An Operating Group is a real working unit inside a Division.

Examples:

```txt
Pump Crew
Site Labour Crew
Install Crew
Shop Counter Team
Kitchen Shift
Delivery Unit
Workshop Bay
```

An Operating Group is where productive labour groups and productive assets are assigned.

## 7. Data Model

### Division Record

```js
{
  division_id,
  division_name,
  division_description,
  is_active,
  sort_order,
  created_at,
  updated_at
}
```

Rules:

```txt
division_id is system-generated
division_name is display only
division_id is the key
inactive divisions remain in history
```

### Operating Group Record

```js
{
  group_id,
  division_id,
  group_name,
  group_description,
  is_active,
  sort_order,
  created_at,
  updated_at
}
```

Rules:

```txt
group_id is system-generated
division_id links the group to a division
group_name is display only
group_id is the key
an operating group must belong to one active division
```

### Labour Group Assignment

```js
{
  assignment_id,
  group_id,
  staff_type_id,
  assignment_percent,
  is_active,
  created_at,
  updated_at
}
```

Rules:

```txt
staff_type_id comes from Labour productive labour groups
Cost Allocation does not create staff_id
Cost Allocation does not calculate Labour cost
Each productive labour group can be assigned up to 100% total across all operating groups
```

### Asset Assignment

```js
{
  assignment_id,
  group_id,
  asset_id,
  assignment_percent,
  is_active,
  created_at,
  updated_at
}
```

Rules:

```txt
asset_id comes from Assets productive asset rows
Cost Allocation does not create asset_id
Cost Allocation does not calculate Asset cost
Each productive asset can be assigned up to 100% total across all operating groups
```

### Overhead Assignment

Overhead is automatic.

```js
{
  assignment_id,
  group_id,
  allocation_method,
  assignment_percent,
  assigned_overhead_amount,
  is_active,
  is_automatic
}
```

Distribution priority:

```txt
1. Labour cost weighted
2. Asset burden weighted
3. Equal split fallback
```

Manual overhead assignment is not part of the default flow.

Each division should produce a cost row:

```js
{
  division_id,
  division_name,
  operating_group_count,
  assigned_labour_cost,
  assigned_labour_hours,
  assigned_asset_burden,

  assigned_overhead_amount,
  total_division_cost,
  division_cost_per_hour,
```

Division rows are aggregated from their operating groups.

## 13. Validation Rules

### Division Validation

A Division is valid when:

```txt
division_id exists
division is active
division has at least one active operating group
all child operating groups are valid
```

### Operating Group Validation

An Operating Group is valid when:

```txt
group_id exists
division_id links to an active division
group is active
group has a valid cost stack or valid assignment state
```

A group may be incomplete if:

```txt
no productive labour assigned
no productive asset assigned
no cost stack exists
```

### Source Pool Validation

Source pools are valid when:

```txt
no productive labour group exceeds 100% assignment
no productive asset exceeds 100% assignment
overhead is fully distributed automatically
```

## 14. Coverage Rules

### Labour Coverage

```txt
staff_coverage_percent =
assigned productive labour groups / available productive labour groups
```

### Asset Coverage

```txt
asset_coverage_percent =
assigned productive assets / available productive assets
```

### Group Coverage

```txt
group_coverage_percent =
valid operating groups / total operating groups
```

### Division Coverage

```txt
division_coverage_percent =
valid divisions / total divisions
```

## 15. Structure Valid Rule

`structure_valid` should be true when:

```txt
at least one active division exists
at least one active operating group exists
no invalid operating groups
no invalid divisions
no productive labour pool over-allocation
no productive asset pool over-allocation
no overhead pool over-allocation
recovery model source requirements are supported
```

It must not require:

```txt
asset_labour_links
linked_staff_count
linked_asset_count
```

## 16. Warning Rules

Visible warnings should focus on:

```txt
no divisions created
no operating groups created
division has no groups
invalid operating groups
productive labour group coverage low
productive asset coverage low
unassigned labour cost
unassigned asset cost
unassigned overhead cost
productive labour pool over-allocated
productive asset pool over-allocated
asset recovery selected but no productive asset assigned
```

Do not show old main-flow warnings like:

```txt
staff is not linked to asset
asset is not linked to staff
```

Those belong only to future advanced capability validation.

## 21. Storage Direction

Storage must support:

```txt
divisions[]
operational_groups[] with division_id
labour_group_assignments[]
asset_group_assignments[]
```

Old operational groups without `division_id` should be handled safely during transition.

Options:

```txt
A. Auto-place old groups into a default division
B. Treat groups without division_id as unassigned and show setup warning
```

Preferred transition:

```txt
Auto-place old groups into a default division named "Main Operations" for compatibility.
```

## 23. Rollout Order

Implement in phases:

```txt
Phase 1 — Lock this contract brief
Phase 2 — Add division storage/default division support
Phase 3 — Add division builders/calculations
Phase 4 — Update selectors to expose divisions
Phase 5 — Update UI to render divisions containing groups
Phase 6 — Update warnings/status for divisions
Phase 7 — Update Recovery Outcome handoff
Phase 8 — Remove old visible link assumptions
```

## 24. Not Allowed

Do not:

```txt
rebuild Labour maths
rebuild Asset maths
change Recovery Summary maths
change Cost Summary maths
use display names as keys
make capability links active in the main flow
make overhead manually assigned by default
rename existing contract outputs without migration
rip out compatibility fields in one pass
```

## 25. Final Definition

Cost Allocation v4.0 is a Division + Operating Groups structural model. It defines how the business is operationally organised, assigns productive labour and productive assets into real operating groups, automatically distributes overhead, aggregates group cost into division cost, and exposes a clean structure-valid output for Recovery Outcome without relying on old capability-link coverage.
