# QS Tools — Future Build Brief

## Quote Engine to Time Management / Live Job Control Layer

## Purpose

This future build extends the Quote Engine into the first practical Layer 2 live-job control system.

The Quote Engine now creates structured quote/job records with:

```txt
Job number
Job name
Client details
Job type
Quote version
Quote price
COG cost
COG markup
Labour hours allowed
Labour hourly cost rate
Calculated labour charge
Calculated labour cost
Calculated labour margin
Recovery surplus / shortfall
Minimum model price
Quote buffer above minimum
```

The next step is to turn a winning quote into a live job and use that live job as the base record for time tracking, works orders, purchase orders, and actual-vs-quoted labour tracking.

---

## Current Completed Direction

The Quote Engine has been changed from a simple quote checker into a quote/job intake and versioning layer.

Completed logic includes:

```txt
New job quote creation
Existing job selection
Automatic quote versioning
Reusable job/client identity
Quote date storage
Winning quote flag
Live job flag
Balanced quote calculation
```

The balanced quote model is now:

```txt
Quote price total
- COG sell total
= Labour charge total
```

And:

```txt
Labour hours allowed
× Labour hourly cost rate
= Labour cost total
```

COG sell is derived from:

```txt
COG cost total
× COG markup %
= COG sell total
```

The main model test is:

```txt
Quote price
- COG cost
- labour cost
= margin left after job costs
```

Then:

```txt
Labour hours allowed
× Cost Summary recovery rate
= Cost Summary recovery required
```

Then:

```txt
Margin left after job costs
- Cost Summary recovery required
= Recovery surplus / shortfall
```

## Key Current Labels

```txt

Quote gap

Hourly gap
→ Hourly recovery surplus / shortfall

Required recovery rate
→ Cost Summary recovery rate

Required price at allowed hours
→ Minimum model price

Price gap
→ Quote buffer above minimum

Max viable hours
→ Max hours before recovery fails
```

Important meaning:

```txt
Recovery surplus / shortfall
= the main good/bad number

Positive = good quote
Negative = quote is short

Quote buffer above minimum
= how much the quote sits above the minimum model price
```

## Time Management App Purpose

The Time Management App records actual labour time against live jobs.

It answers:

```txt
Who worked?
On which job?
On which task?
For how long?
Was the time productive, travel, admin, delay, rework, variation, or other?
How much did the time cost?
How does actual time compare against quoted labour hours?
```

---

## Required MVP Behaviour

The first Time Management build should allow manual time entry.

Required fields:

```txt
Job number
Job name
Client name
Staff name
Staff role
Staff hourly cost rate
Work date
Start time
Finish time
Break minutes
Task
Work category
Notes
```

Calculated fields:

```txt
Gross hours
Net hours
Labour cost total
```

Formula:

```txt
Gross hours = finish time - start time
Net hours = gross hours - break minutes / 60
Labour cost total = net hours × staff hourly cost rate
```

Net hours must never be negative.

---

Non-productive time should still be stored and shown separately.

## Architecture Rules

Follow the locked QS Tools structure:

```txt
page.jsx = orchestration only
hook = state/actions
storage file = local persistence
calculation file = maths
selector file = formatted output/status
components = UI only
```

Do not put calculations inside `page.jsx`.

Do not put localStorage inside components.

Do not connect to Procore, Xero, database, or external APIs yet.

Use localStorage for MVP and make it hydration-safe.

---

```txt
Missing job number
Missing job name
Missing staff name
Missing staff hourly cost rate
Missing work date
Missing start time
Missing finish time
Finish time before start time
Net hours <= 0
Missing task
```

Do not block saving in MVP unless the time calculation is impossible.
