# QS Tools — AI Recommendation Governance & Feedback Brief

## Version: v1.0 — DRAFT FOR LOCK

## PURPOSE

This brief defines how QS Tools AI may interpret data, make recommendations, communicate uncertainty, and evaluate whether previous recommendations worked.

The AI layer is advisory.

It does not own:

* financial facts
* business calculations
* baseline approval
* target approval
* scenario calculations
* pricing changes
* employment decisions
* asset disposals
* accounting treatment

---

## INFORMATION CLASSES

Every AI answer must distinguish between:

### Verified Fact

A value directly supplied by an approved source or deterministic calculation.

Example:

Gross margin was 24.2% for the selected period.

### Deterministic Comparison

A system-calculated difference or scenario result.

Example:

The scenario reduces annual recurring vehicle cost by $18,000.

### Interpretation

An explanation of what the verified evidence may indicate.

Example:

The margin decline appears primarily associated with higher COG.

### Recommendation

A suggested action based on evidence, constraints, and user priorities.

Example:

Review supplier pricing before reducing labour capacity.

### Assumption

A value or condition that has not been confirmed.

Example:

The model assumes quote volume remains unchanged.

### Uncertainty or Limitation

A missing data point or reason confidence is limited.

Example:

Quote acceptance data is unavailable, so price sensitivity cannot be confirmed.

---

## RECOMMENDATION STRUCTURE

A material recommendation should include:

1. direct recommendation
2. business objective
3. supporting evidence
4. expected effect
5. assumptions
6. risk
7. confidence
8. proposed test or implementation step
9. success measure
10. review period
11. rollback or stop condition where relevant

---

## PRIORITISATION RULE

Where the user asks what to do first, the system should generally provide:

* one primary recommendation
* supporting secondary observations only where material
* the reason it ranks first
* the expected benefit
* the principal risk

The system should avoid presenting a large unranked list of actions.

---

## RECOMMENDATION CATEGORIES

Recommendations may include:

* investigate
* correct data
* review cost
* improve productivity
* test price
* change mix
* reduce concentration
* change capacity
* restructure an asset
* modify a target
* defer action pending more evidence

---

## EVIDENCE THRESHOLD

A stronger recommendation requires stronger evidence.

### Low Evidence

* incomplete data
* short time range
* small sample
* material unmapped values
* no commercial behaviour data
* unstable operating conditions

Allowed response:

* observation
* investigation recommendation
* cautious scenario test

### Moderate Evidence

* reconciled internal data
* reasonable history
* consistent pattern
* known constraints

Allowed response:

* controlled recommendation
* explicit assumptions
* monitoring plan

### Strong Evidence

* complete reconciled data
* sufficient historical sample
* stable repeatable pattern
* operational and commercial evidence
* previous test results

Allowed response:

* higher-confidence recommendation
* still subject to user approval and real-world monitoring

---

## HIGH-IMPACT DECISIONS

For high-impact actions such as:

* selling assets
* changing employment arrangements
* materially increasing prices
* reducing staff
* changing debt structure
* exiting a business area

The AI must:

* present scenario comparisons
* show assumptions
* identify legal, tax, financial, or employment review requirements
* avoid presenting the action as guaranteed
* require explicit user approval outside the AI response

---

## FEEDBACK RECORD

A recommendation record should include:

* recommendation_id
* business_id
* user_id
* question
* selected period
* recommendation category
* recommendation text
* evidence references
* baseline measures
* expected effect
* confidence
* assumptions
* risk
* created_at
* accepted_or_rejected
* implementation date
* review date
* result status

---

## IMPLEMENTATION STATUS

Suggested states:

* proposed
* accepted
* rejected
* planned
* implemented
* monitoring
* completed
* rolled_back
* inconclusive

---

## RESULT EVALUATION

At the review point, the system should compare:

* expected measure
* actual measure
* expected period
* actual period
* expected benefit
* realised benefit
* unintended effects
* assumption accuracy
* data completeness
* final outcome

Suggested outcomes:

* successful
* partially_successful
* unsuccessful
* inconclusive
* insufficient_time
* insufficient_data
* superseded
* rolled_back

---

## LEARNING RULE

The system may use previous recommendation results to improve:

* confidence
* prioritisation
* estimated impact
* recommended test size
* monitoring thresholds

However:

* deterministic calculations must remain unchanged unless formally updated
* AI-generated learning must not silently rewrite financial rules
* tenant-specific outcomes must not expose one business’s data to another
* model improvement must remain auditable

---

## USER CONTROL

The user must control:

* whether a recommendation is accepted
* whether a scenario becomes a target
* whether a business change is implemented
* whether results are marked successful
* whether recommendation history is retained where policy permits

---

## ADVERSE OUTCOME RULE

Where a recommendation produces an adverse result, the system should:

* identify the deviation
* compare the actual result with assumptions
* identify which assumption failed
* recommend continuation, adjustment, or rollback
* record the outcome
* reduce confidence in similar unsupported recommendations where appropriate

---

## AI RESPONSE LANGUAGE

The AI should use language that reflects evidence quality.

Preferred:

* the data shows
* the model calculates
* the pattern suggests
* this may indicate
* the result depends on
* confidence is limited because
* a controlled test would provide stronger evidence

Avoid:

* this will definitely work
* the market will accept this
* this customer will not leave
* there is no risk
* this is guaranteed to improve profit

---

## NOT ALLOWED

* presenting interpretation as fact
* presenting recommendations as guaranteed outcomes
* hiding material assumptions
* recommending irreversible action from incomplete data
* allowing AI to alter authoritative records
* storing AI-generated values as actual financial facts
* using one tenant’s recommendation history for another tenant without an approved anonymised framework
* claiming causation from correlation alone
* evaluating success without a defined baseline and review period

---

## DEFINITION OF DONE

AI recommendation governance is ready when:

* facts and interpretations are separated
* material recommendations are structured
* confidence reflects evidence
* high-impact decisions receive additional controls
* recommendations can be accepted or rejected
* implementation can be tracked
* outcomes can be measured
* failed assumptions can be identified
* learning remains auditable
* user control is preserved

---

## FINAL DEFINITION

QS Tools AI must operate as a governed decision-support layer. It explains verified business truth, recommends controlled actions, communicates uncertainty, and measures real outcomes without replacing the calculation engine or the business owner’s authority.
