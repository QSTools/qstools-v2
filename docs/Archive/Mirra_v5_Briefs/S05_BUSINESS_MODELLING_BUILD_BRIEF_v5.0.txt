---

# 1. PURPOSE

Business Modelling is where the user compares the current business against minimum and target models.

It answers:

- What is the business currently doing?
- What is the minimum required model?
- What is the target model?
- What gap exists between actual, minimum, and target?
- What revenue, margin, recovery, or output movement is required?

Business Modelling does not create source truth.

It consumes verified source outputs and lets the user set modelling assumptions.

---

Business Modelling sits after:

- P&L
- Labour
- Assets
- General Overheads
- Revenue / COGS
- Cost Summary
- Revenue Summary
- Business Summary
- Calculation Trace
- Model Readiness

Business Modelling sits before:

- AI-readable business state export
- Dashboard / landing page
- Quote checker
- Business Outcome
- Scenario planning
- Target tracking

---

# 3. CORE RULE

Business Modelling must not recalculate source modules.

It may only:

- read existing output contracts
- read Model Readiness status
- read Business Summary values
- read Revenue Summary values
- compare actual, minimum, and target models
- calculate modelling-only gaps
- expose modelling output contract

It must not:

- overwrite Labour
- overwrite Assets
- overwrite General Overheads
- overwrite Cost Summary
- overwrite Revenue Summary
- overwrite Business Summary
- override Model Readiness
- infer missing source truth
- silently fix incomplete modules

---

# 4. MODELLING LAYERS

Business Modelling should present three layers:

## 4.1 Actual Model

The actual model reflects the current source outputs.

Examples:

- actual revenue
- actual direct costs
- actual margin pool
- actual business cost burden
- actual productive output
- actual recovery per driver
- actual gross margin
- actual net position where available

## 4.2 Minimum Model

The minimum model shows the business break-even or required recovery baseline.

Examples:

- minimum required revenue
- minimum required recovery rate
- minimum margin pool
- minimum productive output requirement
- minimum cost recovery requirement

## 4.3 Target Model

The target model is user-set.

Examples:

- target revenue
- target margin percent
- target owner profit
- target recovery rate
- target productive output
- target utilisation
- target surplus

Target model values are modelling assumptions only.

They must not write back into source modules.

---

# 5. MODEL READINESS GATE

Business Modelling must display Model Readiness status.

If Model Readiness is blocked:

- Business Modelling should still render
- source values may display
- downstream trust status must show blocked
- target inputs may remain available for planning
- outputs must be clearly marked not trusted

If Model Readiness is ready or warning:

- Business Modelling can display model comparisons
- warnings remain visible

---

business_modelling_output_contract = {

# 10. FINAL PRINCIPLE
