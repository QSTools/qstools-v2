## Methodology notes worth carrying forward

- All JSX/JS/CSS edits after the initial two files were done via the Apply-Patch (IndexOf/Substring) function from the Working Conventions doc, one small anchored patch at a time, build after every single one - not full-file rewrites. The two initial files (before this discipline was re-established mid-session) were done via direct WriteAllText since they didn't exist yet - acceptable for brand-new files, but Apply-Patch is required for anything with existing content.
- PowerShell here-strings must use single-quoted delimiters (@' ... '@), not double-quoted (@" ... "@), when the content includes JS template literals with ${...} syntax - double-quoted here-strings make PowerShell try to interpret those as its own variable syntax and throw a parser error. This bit once this session (the format_currency helper's template literal) - single-quoted here-strings avoid it entirely and should be the default for any JS/JSX content going forward.
- A live "0.00 in amber" gauge reading mid-session was NOT a bug - the hook/selector/CSS were all confirmed structurally sound (brace-balanced CSS, correct prop wiring, correct exports) before the actual cause was found: the underlying revenue input was at a value that genuinely produced an undefined/zero ratio at that moment. Changing the input to a realistic value immediately produced a correct 0.96 reading. Lesson: a 0.00 gauge display isn't necessarily a code bug - check the live underlying data/input state first before assuming something broke.
