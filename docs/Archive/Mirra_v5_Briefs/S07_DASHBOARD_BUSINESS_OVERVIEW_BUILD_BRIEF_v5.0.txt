---

# 1. PURPOSE

Dashboard / Business Overview gives the user a simple top-level view of the current business state.

It answers:

- Is the model trusted?
- Is the business ready for modelling?
- What is the selected business model?
- What is the current business position?
- What are the main blockers or warnings?
- What should the user review next?

Dashboard does not create source truth.

It reads existing export, readiness, modelling, and summary outputs.

---

# 2. POSITION IN SYSTEM

Dashboard sits after:

- Model Readiness
- Business Modelling
- AI-readable Business State Export
- Business Summary
- Revenue Summary
- Cost Summary

Dashboard sits before:

- deeper drill-downs
- reports
- quote checker
- user-facing business review pages

---

# 3. CORE RULE

Dashboard must not calculate source business values.

It may only:

- read AI-readable Business State Export
- read trust state
- read downstream permissions
- display selected model summary
- display blockers and warnings
- link the user to source pages for review

It must not:

- overwrite source modules
- infer missing source truth
- patch missing values
- override trust state
- create business calculations
- become a source module

---

# 4. FIRST IMPLEMENTATION SCOPE

First implementation should create:

- /business-overview route
- overview status cards
- trust state card
- downstream permissions card
- selected model summary
- blockers/warnings summary
- next actions list

No database.

No external AI.

No reporting export.

No quote checker wiring yet.

---

# 7. FINAL PRINCIPLE

Dashboard reflects the current business state.

It does not decide or change the business state.
