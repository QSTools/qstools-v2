---
# 1. PURPOSE

Build Calculation Trace as a read-only supporting module that shows how a selected output value was built.

The first implementation target is the locked pilot chain for Required Recovery Per Driver.

Calculation Trace must help users and developers understand lineage, trust state, and dependency paths without changing any business calculation.

---
# 2. LOCKED PILOT INPUT

The implementation must use the locked pilot lineage map as its source reference:

S03_CALCULATION_TRACE_PILOT_LINEAGE_MAP_v5.0.txt

The pilot is locked within source-module-level scope.

It is manually verified but not yet code-verified.

---
# 3. NON-NEGOTIABLE RULES

Calculation Trace must not:

- calculate values
- own formulas
- duplicate source truth
- infer missing lineage
- repair broken chains silently
- write back to source modules
- become a downstream dependency for Cost Summary, Business Summary, Business Outcome, or Business Modelling

Calculation Trace may only display verified nodes, verified edges, formula text, source notes, scope boundaries, and incomplete states.

Final principle:

Calculation Trace shows how a number was built. It does not decide what the number is.

---
# 4. FIRST IMPLEMENTATION SCOPE

Implement the pilot chain only:

- Business Summary / Required Recovery Per Driver
- Business Summary / Total Cost Burden
- Business Summary / Activity Driver Value
- Cost Summary / Total Cost Burden
- Cost Summary / Total People Cost Annual
- Cost Summary / Total Asset Cost Annual
- Cost Summary / Total Business Overheads
- Labour / Total People Cost Annual
- Labour / Total Productive Output
- Assets / Total Asset Cost Annual
- General Overheads / Total General Overheads
- General Overheads / Total Business Overheads
- Revenue / COGS unit-driver outputs for product/unit mode

Do not extend into Business Outcome, Business Modelling, full P&L tracing, or UI design beyond what is required to display the pilot trace.

---
# 5. DATA MODEL

Use two read-only structures:

trace_nodes
trace_edges

## 5.1 trace_nodes fields

- node_id
- module_name
- variable_name
- display_label
- value_source
- formula_text
- is_root_input
- brief_reference
- last_verified_against
- source_file
- implementation_status
- notes

source_file must remain blank, null, or unavailable until code-level verification is completed.

Do not invent source_file values.

## 5.2 trace_edges fields

- edge_id
- from_node_id
- to_node_id
- relationship_type
- notes
- implementation_status

Allowed relationship_type values:

- direct_input
- weighted_component
- conditional_input
- sum_component

---
# 6. INITIAL STORAGE APPROACH

For the first build, the trace map may be implemented as a static local data file generated from the locked pilot map.

Recommended location:

lib/calculation-trace/calculationTracePilotMap.js

Recommended exports:

- traceNodes
- traceEdges
- getTraceNode(nodeId)
- getIncomingEdges(nodeId)
- getOutgoingEdges(nodeId)
- getUpstreamTrace(nodeId)
- getDownstreamTrace(nodeId)

The static map must mirror the locked pilot brief and must not introduce new formulas or links.

---
# 7. SELECTOR RULES

Selectors must be pure.

They may:

- read traceNodes
- read traceEdges
- return upstream paths
- return downstream paths
- flag missing endpoints
- flag incomplete scope boundaries
- group trace paths by module

They must not:

- calculate business values
- mutate trace data
- call source module calculators
- infer missing edges
- change node values

---
# 8. PAGE / COMPONENT SCOPE

Create a read-only Calculation Trace view.

Suggested route:

app/calculation-trace/page.jsx

Suggested components:

- CalculationTracePage
- TraceOutputSelector
- TraceNodeCard
- TraceEdgeList
- TracePathPanel
- TraceScopeBoundaryNotice
- TraceManualProofPanel

Initial selected output:

business_summary.required_recovery_per_driver

---
# 9. REQUIRED UI BEHAVIOUR

The page should show:

- selected output node
- upstream contributing nodes
- formula text for each node
- relationship type for each edge
- module owner for every node
- root-input markers
- known deferred boundaries
- manual re-derivation proof result
- code verification status

The page should clearly show that the trace is read-only and not a calculator.

---
# 10. REQUIRED STATUS STATES

Use clear status labels:

- verified_in_brief
- manual_pilot_passed
- code_verification_deferred
- out_of_scope_boundary
- incomplete
- missing_endpoint

Do not use green/red success styling as a global decision signal.

Use neutral status wording consistent with the Mirra UI system.

---
# 11. MANUAL PROOF PANEL

The first build must include the locked manual re-derivation result:

total_cost_burden = 245,000
activity_driver_value = 1,500
required_recovery_per_driver = 245,000 / 1,500
required_recovery_per_driver = 163.3333333333
rounded display = $163.33 per productive hour

This is a representative proof only.

It must not be used as live business data.

---
# 12. DEFERRED WORK

Deferred from this implementation:

- code-level verification
- source_file population
- P&L-internal mapped source tracing
- full Module Reconciliation trace layer
- Business Outcome trace
- Business Modelling trace
- AI explanation layer
- database-backed trace storage
- user-editable trace map

---
# 13. ACCEPTANCE CRITERIA

The implementation is acceptable when:

- Required Recovery Per Driver can be selected as the output node
- upstream trace path displays back to pilot-scope root inputs
- all displayed nodes match the locked pilot map
- all displayed edges match the locked pilot map
- manual re-derivation result is shown
- code verification is clearly marked deferred
- source_file is not invented
- P&L / Module Reconciliation is shown as deferred boundary
- no source module calculations are duplicated
- no downstream module depends on Calculation Trace

---
# 14. BUILD ORDER

1. Create static trace data from the locked pilot map.
2. Create pure selectors for node and edge traversal.
3. Create read-only page shell.
4. Add output selector with Required Recovery Per Driver as initial target.
5. Add upstream trace path display.
6. Add node cards and edge relationship labels.
7. Add scope boundary notices.
8. Add manual proof panel.

---
# 15. FINAL PRINCIPLE

Calculation Trace shows how a number was built. It does not decide what the number is.
