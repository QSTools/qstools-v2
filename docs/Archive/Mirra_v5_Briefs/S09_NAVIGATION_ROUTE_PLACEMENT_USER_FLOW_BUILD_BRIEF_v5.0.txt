# 1. PURPOSE

S09 makes the completed user-facing routes discoverable and usable from the main app flow.

It answers:

- Where should Business Overview sit?
- Should Business Overview become the default landing page?
- Where should Quote Checker sit?
- Where should AI Business State sit?
- How should users move between readiness, modelling, overview and quote checking?
- Which routes are user-facing and which are developer/admin-facing?

S09 does not create new business calculations.

It improves route placement, navigation and user flow.

---

# 4. CORE RULE

Navigation must not change source truth.

Navigation may only:

- expose existing routes
- group routes clearly
- improve user movement through the system
- add links or route cards
- optionally redirect the home route

Navigation must not:

- calculate business values
- alter source modules
- alter output contracts
- override readiness or trust state
- hide blockers or warnings
- introduce new modelling logic

# 6. ACCEPTANCE CRITERIA

The stage is accepted when:

- relevant navigation files are inspected first

- Quote Checker is discoverable

- Calculation Trace integrity still passes
- npm run build passes
- git status is clean after commit

---

# 7. FINAL PRINCIPLE

Navigation guides the user through the model.

It does not change the model.
