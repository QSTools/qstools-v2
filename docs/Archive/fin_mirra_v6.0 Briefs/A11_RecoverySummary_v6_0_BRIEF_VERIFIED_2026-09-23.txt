===============================================================================
1. WHAT WAS WRONG
===============================================================================

calculateRecoverySummary.js used productive_asset_cost as the full productive
asset burden. That field is OWN cost only (finance interest). It excludes the
General Overheads running-cost pools assigned to productive assets (fuel,
insurance, repairs, registration). In hours mode, General Overheads is already
net of those pools, so the pools were missing from every recovery stream.

Effect: required asset recovery rate, asset_recovery_cost, the suggested split
basis and the output shares (labour / asset / overhead) were all wrong.
Recovery streams summed to less than the cost burden by the whole pool amount.

===============================================================================
2. CORRECTION TO THE ASSETS BRIEF FIX SPEC
===============================================================================

The Assets brief said useRecoverySummary "already passes"
productive_asset_assigned_overhead_cost_annual in (~line 149). It does not.
Lines 148-153 of useRecoverySummary are the OUTPUT contract passthrough. The
calculation receives Business Summary outputs spread at top level plus the
Assets contract nested as input.assets. Business Summary does not publish the
pool figure. The fix therefore reads it from input.assets (the same source the
output passthrough uses), with input.* checked first.

===============================================================================
3. WHAT CHANGED (lib/calculations/recovery-summary/calculateRecoverySummary.js)
===============================================================================

  P1 New constants: productive_asset_assigned_overhead_cost (from the Assets
     contract) and productive_asset_recovery_cost = own + pools.
  P2 required_asset_recovery_rate uses the full burden.
  P3 Suggested split basis uses the full burden.
  P4 asset_recovery_status base check uses the full burden.
  P5 Hours-mode asset_recovery_cost = full burden.
  P6 asset_recovery_included uses the full burden.
  P7 Publishes productive_asset_assigned_overhead_cost and
     productive_asset_recovery_cost_annual. productive_asset_cost and
     productive_asset_cost_annual are UNCHANGED (own cost) - naming trap.
  P8 Returns asset_recovery_status. It was computed but never returned, so the
     card always showed "Not selected" and the output contract published
     undefined (dropped-field bug class (b)). Found live during this fix.

P4 and P6 go slightly beyond the Assets brief spec: they keep the "has a
productive asset base" checks consistent with the stream they describe.

No UI change needed: the "Productive asset cost" row on the Recovery Summary
evidence panel displays asset_recovery_cost, not productive_asset_cost.

  - Legacy useBusinessOutcome: productive asset cost is built from

    (businessOutcomeCalculations.js 122-123). asset_recovery_cost is used only

  - useCostAllocation.js 99-101: asset_recovery_cost feeds

    raw calculated object never leaves the hook.
