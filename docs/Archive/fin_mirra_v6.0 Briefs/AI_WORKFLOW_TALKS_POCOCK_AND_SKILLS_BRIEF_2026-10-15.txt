1. WHY THIS BRIEF EXISTS
===============================================================================
The owner wants to run this project as efficiently as possible on a usage-limited
plan. The talks were mined for ideas that fit the actual setup: chat-based work,
PowerShell patching, no agent running inside the repo. This brief records what
the talks say, what was adopted, what was found in the repo, and what was parked.

===============================================================================
2. WHAT THE TALKS SAY (condensed, in priority order for Mirra)
===============================================================================
 P1  Slice work vertically (thin end-to-end slices), not layer by layer, so
     feedback arrives early.
 P2  Feedback loops set the ceiling on AI output quality. A green build is a weak
     loop; stronger automated checks make the agent better.
 P3  Model quality degrades as a chat grows (about 100k tokens regardless of
     window size). Keep sessions small; hand off through a document, not context.
 P4  Align on the design before building (the "grill me" interview), and keep
     tasks small and independently grabbable.
 P5  Deep modules: small interface, lots inside, one test boundary. Design the
     interface yourself, delegate the inside.
 P6  QA findings become new backlog items, not ad hoc fixes.
 S1  Save proven code instead of regenerating it each time.
 S2  Precise descriptions so only the right material loads; keep always-loaded
     context small.
 S3  Turn corrections into durable rules: classify the cause (process, missing
     context, weak rule, unreliable code) and fix it in the smallest durable place.
 S4  Verify with evidence outside the first draft; state acceptance criteria
     before the work, not after.
