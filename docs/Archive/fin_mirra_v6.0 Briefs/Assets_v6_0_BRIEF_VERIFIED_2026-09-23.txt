1. WHAT ASSETS ACTUALLY DOES (code truth, 2026-09-23)
===============================================================================

The v4 brief describes a much richer module than the code implements. Where they
differ, THIS SECTION is the truth; Section 3 lists the gaps.

FILES
  hooks/useAssets.js                         orchestrator (343 lines)
  hooks/assets/assetOutputContract.js        buildAssetsOutputContract (the contract)
  hooks/assets/assetHookUtils.js             pool keys, pool summary, utilisation/rate
  lib/calculations/assetCalculations.js      calculateAssetOutputs (finance, interest)
  lib/storage/assetStorage.js                useAssetStorage, sanitize, save/load
  lib/selectors/assets/assetStatusSelectors.js   buildAssetStatus (warnings, guardrail)
  lib/selectors/assets/assetCardSelectors.js     buildAssetCard (page card values)
  lib/selectors/assets/assetOverheadPoolSelectors.js  status-side pool summary
  lib/selectors/assets/assetSelectorUtilisation.js    live annual hours for status
  components/assets/AssetStatusStrip.jsx     now rendered on /assets (A23)
  app/assets/page.jsx

STORAGE
  qs_tools_asset_state   = the editor draft (one asset being edited)
  qs_tools_saved_assets  = the saved asset list (what everything downstream reads)
  qs_tools_fixed_asset_register_state_v1 = Fixed Asset Register import (separate)
  Save effects are guarded by has_hydrated (the audit script flags this as a gap
  only because it does not recognise that name - false positive).
  sanitizeSavedAssetRecord re-runs calculateAssetOutputs on EVERY read, so
  finance interest is refreshed on each page load. It passes no business weeks,
  so the stored utilisation_hours_annual always uses 48 weeks (or the override).

ASSET TYPE
  asset_type "productive" | "support" (normalizeAssetType maps non_productive ->
  support; anything unrecognised -> productive). Support assets: utilisation and
  rate forced to 0. Active = !is_retired (is_active is stored and kept in sync by
  the form, but no filter reads it).

PER-ASSET OWN COST
  total_asset_cost_annual = asset_interest_annual + running_cost_annual(=0, hard-coded)
  asset_interest_annual   = purchase_price x (1 - elapsed_days / (term_years x 365.25))
                            x interest_rate, only while finance is active
                            (not paid off, term not ended). "elapsed" is to TODAY.
  Principal and total finance payment are computed (amortising payment formula)
  and exposed as cash_flow_support only - never in cost. Correct per brief s17.

UTILISATION
  utilisation_hours_per_week = scheduled - downtime (if scheduled set), else the
    stored value, else default 40 (productive only).
  annual weeks = asset_annual_weeks_override -> Opening Hours annual_open_weeks
    -> 48 fallback. (Brief said a fixed 48; the code's chain is deliberate.)
  utilisation_hours_annual = weekly hours x annual weeks.

ASSET OVERHEAD POOLS (running-cost transfers from General Overheads)
  Six keys: asset_fuel_pool, asset_insurance_pool, asset_repairs_maintenance_pool,
    asset_registration_compliance_pool, asset_consumables_pool,
    asset_finance_interest_pool. Pool amounts come from General Overheads
    (generalOverheadPoolSelectors build_asset_overhead_pools), built from the
    NET active_amount, i.e. after Assets' calculated interest has been removed
    from the flagged P&L interest row - so no interest double count (A19 closed).
  Each asset stores asset_overhead_pool_assignments {pool_key: amount}.
  Contract: effective assignment = raw, scaled pro-rata only if the pool is
    over-assigned (see A3).
  asset_recovery_cost_annual = total_asset_cost_annual + effective assignments.
  Cost Summary adds total_allocated_asset_overhead_cost_annual to Assets and
    subtracts the same figure from General Overheads, so the transfer moves cost
    between the two lines without changing the total (brief s31 satisfied).

RATE
  required_asset_recovery_rate (per asset, contract) =
    (asset_recovery_cost_annual + depreciation_addition) / utilisation_hours_annual
    depreciation_addition = estimated_annual_depreciation only when
    include_depreciation_in_cost is true (register-linked assets) - see A2.
  productive_asset_recovery_rate (contract, blended) =
    productive_asset_recovery_cost_annual / total productive utilisation hours.
  Status (Assets page) productive_asset_recovery_rate: same definition since
    26f4be7 (was own cost only - A10).

GUARDRAIL / STATUS
  buildAssetStatus computes asset_pool_guardrail_status (blocked if any pool
  over-allocated; review_required if any pool under-allocated / no source /
  review; else ready) as brief s33 describes. assets_ready is false on
  over-allocation. Since 26f4be7 the guardrail is in the output contract (A18).
  Warnings are plain strings (not the brief's structured objects).

2. OUTPUT CONTRACT (as implemented) - field meanings
===============================================================================

buildAssetsOutputContract returns (key fields):
  assets / active_assets        row list (identical arrays) - per-asset rows with
                                effective pool assignments, recovery cost, rate
  assets_ready, no_active_assets_confirmed, has_productive_asset_recovery_base
  asset_pool_guardrail_status   NEW 26f4be7
  productive_asset_count, support_asset_count
  total_asset_cost_annual       OWN cost, all live assets (interest only today)
  productive_asset_cost         OWN cost, productive only - EXCLUDES pools
  productive_asset_cost_annual  alias of productive_asset_cost
  productive_asset_assigned_overhead_cost_annual   pools assigned to productive
  productive_asset_recovery_cost_annual            own + pools, productive
  support_asset_cost            OWN cost, support only - EXCLUDES pools
  support_asset_assigned_overhead_cost_annual
  total_allocated_asset_overhead_cost_annual (+ alias total_assigned_...)
  total_asset_recovery_cost_annual   own + pools, all live assets
                                     = Cost Summary's Assets line
  total_productive_asset_utilisation_hours_annual, productive_asset_recovery_rate
  asset_overhead_pools, asset_overhead_pool_assignment_summary (+ aliases
    asset_related_overhead_pool, asset_related_pool_total,
    total_asset_related_overhead_pool_amount, asset_related_assigned_to_assets,
    asset_related_unassigned_cost / _balance, total_unassigned_asset_related_...)
  asset_review_required         true when any pool balance remains unassigned (A6)
  asset_overhead_assignment_warnings
  total_asset_interest_annual, finance_cost_annual, cash_flow_support,
  legacy_display.running_cost_annual (always 0)

!! NAMING TRAP (A11): productive_asset_cost / support_asset_cost are OWN cost
   and EXCLUDE assigned pools. Any consumer wanting the full asset burden must
   add *_assigned_overhead_cost_annual (Business Outcome does this correctly) or
   read *_recovery_cost_annual. Do NOT change the contract field to include
   pools - Business Outcome would then double count.

Also returned by useAssets() alongside the contract (NOT inside it):
  status, card, active_assets (a SECOND, separately built row list - uses RAW
  pool assignments, no pro-rata; see A3), business_default_annual_weeks,
  asset_finance_pnl_match.

v5.0 Pass 4 decisions, now recorded:
  Reference wrappers (not business metrics): asset_detail (Cost Summary),
    asset_outputs (Recovery Summary), asset_overhead_pools, asset_recovery_overlay
    (Cost Allocation), assets, general_overheads, live_assets, saved_assets,
    asset_output_contract, assets_output (Model Readiness).
  Rejected helpers: build_asset_recovery_overlay, safe_array, safe_number.
  asset_operator: comes from lib/selectors/quickStartSelectors.js - a Quick Start
    name collision, NOT an Assets field (same pattern as business_type in P2.1).
  The v5 audit assigned fields to Assets by name match; several listed
  "Assets" fields are produced by Cost Summary / reconciliation
  (e.g. total_general_overheads_before_asset_assignment,
  assigned_asset_overhead_cost_annual, excluded_asset_finance_interest_total).
