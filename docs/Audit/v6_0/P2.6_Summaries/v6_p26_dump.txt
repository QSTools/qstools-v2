  13: ===============================================================================
  14: 1. WHAT WAS WRONG
  15: ===============================================================================
  16: 
  17: calculateRecoverySummary.js used productive_asset_cost as the full productive
  18: asset burden. That field is OWN cost only (finance interest). It excludes the
  19: General Overheads running-cost pools assigned to productive assets (fuel,
  20: insurance, repairs, registration). In hours mode, General Overheads is already
  21: net of those pools, so the pools were missing from every recovery stream.
  22: 
  23: Effect: required asset recovery rate, asset_recovery_cost, the suggested split
  24: basis and the output shares (labour / asset / overhead) were all wrong.
  25: Recovery streams summed to less than the cost burden by the whole pool amount.
  26: 
  27: ===============================================================================
  28: 2. CORRECTION TO THE ASSETS BRIEF FIX SPEC
  29: ===============================================================================
  30: 
  31: The Assets brief said useRecoverySummary "already passes"
  32: productive_asset_assigned_overhead_cost_annual in (~line 149). It does not.
  33: Lines 148-153 of useRecoverySummary are the OUTPUT contract passthrough. The
  34: calculation receives Business Summary outputs spread at top level plus the
  35: Assets contract nested as input.assets. Business Summary does not publish the
  36: pool figure. The fix therefore reads it from input.assets (the same source the
  37: output passthrough uses), with input.* checked first.

  24:     labour_data.total_staff_recovery_hours ?? labour_data.total_productive_output
  25:   );
  26:   const labour_recovery_hours = to_number(business_recovery_hours);
  27:   const total_recovery_hours =
  28:     labour_recovery_hours > 0 ? labour_recovery_hours : total_productive_output;
  29:

  35:     general_overhead_data.total_general_overheads

  39:     total_asset_cost_annual + total_business_overheads;
  40:

  42:     total_people_cost_annual +
  43:     total_asset_cost_annual +
  44:     total_business_overheads;
  45: 
  46:   const required_revenue = total_cost_burden;
  47:

  49:     total_recovery_hours > 0
  50:       ? required_revenue / total_recovery_hours
  51:       : 0;

  54:   const required_labour_burden_rate =
  55:     total_productive_output > 0 ? total_cost_burden / total_productive_output : 0;

  87: ## 4. The three recurring gotchas
  88: 
  89: **1. The blurb has two separate prop lists.** File: BusinessOutcomeTruthSituationSummary.jsx. A new prop must be added in three places: the Card's JSX call, the wrapper's destructuring, and the wrapper's forwarding call into build_situation_summary. Miss the middle one and the paragraph silently doesn't render.

  91: **2. The selector explicitly lists every field it returns.** File: businessOutcomePerSourceRevenueSelectors.js, inside selectBusinessOutcomePerSourceRevenue(). A new field on the hook's raw return object will NOT reach the Card unless also added here.
  92: 
  93: **3. Links into "How the Numbers Are Calculated" need the pre-toggle.** Any ScrollToSectionLink or scroll_to_section() call pointing there needs pre_toggle_labels: ["Show breakdown"] in addition to ancestor_ids.
  94: 
  95: **4. THERE ARE TWO true_cost SOURCES, ONE STALE - confirmed 2026-09-18, cost a full session to find.** The selector's group_sources_by_group()/group_true_cost (businessOutcomePerSourceRevenueSelectors.js) sums RAW, per-row true_cost - it has NEVER been touched by the non-productive cost injection (that injection only ever lives inside apply_real_capacity/apply_real_capacity_v2's own ephemeral `groups` calculation, never written back to the original row objects). The CORRECT, injected figure lives ONLY in real_capacity.group_real_capacity[].true_cost (View A) and view_b.real_capacity.group_real_capacity[].true_cost (View B - this field did not even exist on View B's return object until 2026-09-18, root cause of that day's bug). ANY table or component that builds its own cost figure by re-summing row.true_cost or reading group_true_cost/entry.total_cost from merge_groups_by_id()/merge_groups_by_id_real_capacity()/merge_view_b_groups() WITHOUT cross-referencing group_real_capacity's own true_cost is showing the stale figure. Confirmed fixed in: CostBuildUpTable, merge_view_b_groups (both call sites: ViewBRealCapacityLedger and ViewBCostBuildUpTable). NOT yet checked: any other component that might independently read group_true_cost/entry.total_cost - grep both terms before trusting a new or unfamiliar cost display.
