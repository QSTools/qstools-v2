# 6. SOURCE VERIFICATION CLASSIFICATIONS

Each trace node must be classified as one of:

## 6.1 source_owned

The file directly calculates or derives the value.

## 6.2 output_contract_passthrough

The file passes through a value owned by another module.

## 6.3 selector_shape

The file shapes or formats the value for UI but does not own the calculation.

## 6.4 storage_shape

The file stores a calculated or imported value but does not own the calculation.

## 6.5 deferred

The source owner is not proven yet.

---

# 7. SOURCE_FILE POPULATION RULES

Populate source_file only when one of these is true:

- the value is directly calculated in that source file
- the value is directly returned from that source file as part of the module output contract
- the value is clearly consumed from another module and passed through as an output contract value
- the source file is the highest-confidence owner identified by code inspection

Do not populate source_file when:

- the value only appears in UI formatting
- the value only appears in a warning message
- the value only appears in downstream modules
- the value appears only as a fallback or compatibility alias
- the source ownership is ambiguous
