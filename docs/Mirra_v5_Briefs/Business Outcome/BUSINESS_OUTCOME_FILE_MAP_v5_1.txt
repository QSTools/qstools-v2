## 1. The data flow (read this first)

hooks/useBusinessOutcomePerSourceRevenue.js
  (raw calculations, returns per_source_result)
        v
lib/selectors/business-outcome/businessOutcomePerSourceRevenueSelectors.js
  selectBusinessOutcomePerSourceRevenue() - RESHAPES the raw result into per_source
        v
components/business-outcome-truth/BusinessOutcomePerSourceRevenueCard.jsx
  (the main page Card - receives per_source as a prop, renders everything)
        v
  passes pieces of per_source down as props to sub-components:
  - BusinessOutcomeTruthSituationSummary.jsx (the blurb)
  - BusinessOutcomeViewABComparisonTable.jsx
  - BusinessOutcomeCapacityCoverageGapTable.jsx
  - BusinessOutcomeHealthGauge.jsx
  - BusinessOutcomeHealthGaugeExplainer.jsx (NEW 2026-09-12)
  - RealCapacityLedger, AssumedCapacityLedger, CostBuildUpTable (defined inline in the Card itself)
  - ViewBRealCapacityLedger, ViewBCostBuildUpTable (View B equivalents, also inline in the Card)

**The #1 rule that bites every time:** a new field added to the hook's return object does NOT automatically reach the Card. It must ALSO be added to the selector's return object (selectBusinessOutcomePerSourceRevenue's own return { ... }, near the existing view_b:, capacity_coverage_gap:, health_gauge: lines). Search per_source_result. in that file to see the existing pattern before adding a new one.

## 4. The three recurring gotchas

**1. The blurb has two separate prop lists.** File: BusinessOutcomeTruthSituationSummary.jsx. A new prop must be added in three places: the Card's JSX call, the wrapper's destructuring, and the wrapper's forwarding call into build_situation_summary. Miss the middle one and the paragraph silently doesn't render.

**2. The selector explicitly lists every field it returns.** File: businessOutcomePerSourceRevenueSelectors.js, inside selectBusinessOutcomePerSourceRevenue(). A new field on the hook's raw return object will NOT reach the Card unless also added here.

**3. Links into "How the Numbers Are Calculated" need the pre-toggle.** Any ScrollToSectionLink or scroll_to_section() call pointing there needs pre_toggle_labels: ["Show breakdown"] in addition to ancestor_ids.

## 5. Field-name traps

- per_source.labour_groups[] / asset_groups[] use .group_modelled_revenue / .group_true_cost, NOT .modelled_revenue/.total_cost.
- per_source.materials uses .revenue for View A's residual figure, NOT .modelled_revenue.
- per_source.view_b.labour_sources[] / .asset_sources[] / .materials DO use .modelled_revenue directly.
- real_capacity.group_real_capacity[] has both naive_net_profit and final_net_profit - pick deliberately.
- Per-source direct/overhead cost IS tracked separately: direct_cost, overhead_share, summed to true_cost - confirmed in useBusinessOutcomePerSourceRevenue.js and carried through the selector as group_true_cost, group_overhead_share.
- Always grep for an existing working consumer of a field before writing new code that reads it.

## 7. Standing conventions & untouchable files

Full detail in "Working_Conventions - PowerShell Patching, CSS, and Numeric Verification" (repo root). Summary:
- All edits via PowerShell, one command at a time, targeted Apply-Patch (IndexOf/Substring) patches - never full-file rewrites once a file has real content worth preserving.
- .NET UTF-8-no-BOM file I/O only, never Set-Content/Get-Content for writing.
- Build after every single patch.
- Five pre-existing files remain untouched unless specifically working on them (confirm via git status): components/business-modelling/BusinessModellingLeverCard.jsx, components/layout/SidebarNavigation.jsx, docs/Mirra_v5_Briefs/S22 - ASSET FINANCE INTEREST EXCLUSION & COVERAGE CHECK.txt, lib/calculations/businessModellingIndependentCalculations.js, lib/selectors/general-overheads/generalOverheadCategorySelectors.js.
- CSS: reuse existing classes/variables before inventing new ones; scope new styling to a new class, never modify a shared class.
