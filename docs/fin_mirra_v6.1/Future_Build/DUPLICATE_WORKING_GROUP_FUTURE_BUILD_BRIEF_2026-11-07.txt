===============================================================================
1. PROBLEM (owner's words in plain terms)
===============================================================================
A fleet of similar machines each needs its own working group so that each machine's cost and margin are right: twelve concrete mixer bowls bought at different times (different price and finance), a digger fleet at one hourly rate, a van fleet. Putting all twelve in ONE group distorts the per-hour rates (group asset hours are the MAX of the assets, COST_ALLOCATION_BRIEF R4, and the labour cap is MIN(asset hours, labour hours), R5; total cost is right, per-hour rates are not). Building twelve groups by hand means assigning the same people, overhead and cost of sales twelve times, which is the duplication the owner wants to avoid. Each bowl is the same shape every time; only the asset (and so the finance) differs.

===============================================================================
2. DECISION (owner, 2026-11-07)
===============================================================================
D1  Each similar asset gets its OWN working group inside the SAME operating group. (Direction, replaces the earlier intent of one group holding all twelve: UNITS_MODE Addendum 1 item 8 and COST_ALLOCATION Addendum 14 item 3.)
D2  A DUPLICATE button on a working group copies the group with its assignments inside the same operating group; the user then picks which asset is assigned. Assets stay one record per machine (a quantity field on an asset stays REJECTED: UNITS_MODE Addendum 1 item 9).
D3  Not units specific: works in hours mode (a digger fleet) and units mode (twelve bowls). Logged as its own brief, next to the shared calculator brief.
D4  Duplicate group and shared calculator together mean: build the first group and calculator once, then per extra machine only pick the asset and pick "use existing calculator".

===============================================================================
4. DESIGN REQUIREMENTS (PROPOSED, ask before any storage field)
===============================================================================
R1  The action creates a new group in the same operating group with a new id and a name derived from the source (rename allowed). Owner's explicit yes on the stored shape before any build.
R2  The copy carries every assignment the source has EXCEPT the asset: labour assignments, overhead assignments and (when it exists) the cost of sales assignments. The asset field starts empty and the user must pick the next asset; a group with no asset is shown as incomplete, never silently priced.
R3  Assignment percentages: copy them as they are, then show them to the user. The copy must not change the combined total across groups without the user seeing it (a percentage of one person's time assigned to twelve groups can exceed 100 percent in total; check how Cost Allocation validates this today and surface it, do not hide it).
R4  If the source group is linked to a Rate Builder calculator, the copy offers "use existing calculator" pointing at it (SHARED_CALCULATOR D1). Never copy the calculator record itself.
R5  Every new stored field the copy touches is added to every explicit field list (bug class b), and the copy goes through the same storage helper path as a normal group (including the Model mode storage helper, which must pass it through unchanged with Model mode off).
R6  The new group must go through the same readiness, warnings and hard blocks as a hand-built group (for example the L11 labour block). Duplicating must not be a route around a check.

 1. [DECISION, owner, explicit yes] The duplicate group copy is agreed as a stored shape. It copies the group SHELL: a new working group in the same operating group with the same overhead and cost of sales assignments, plus the stream (a working group now carries a stream link, COST_ALLOCATION Addendum 16 item 1; a group with no stream shows incomplete).
 2. [DECISION, owner, CHANGES R2 and R3] Labour assignments and the asset are NOT copied. Twelve bowls need twelve drivers, so each copy gets its own driver and its own bowl assigned afterwards. Owner's proviso (distribution must update automatically) is met by the existing behaviour; confirm in the live proof.
 4. [DECISION, owner] The existing Cost Allocation unassigned figure is the check. It reaches zero only when all drivers and bowls are assigned; until then the warning stays and blocks later steps. [ACCEPTANCE CHANGE] A3 becomes: the copy carries overhead, cost of sales and stream assignments and leaves labour and asset empty; the group shows unassigned until both are assigned, and the unassigned figure reaches zero when all are assigned. A2 still applies with drivers assigned by hand after each copy.
