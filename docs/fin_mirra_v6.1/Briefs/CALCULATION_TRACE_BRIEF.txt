===============================================================================
1. INTENT
===============================================================================
The trace page is a click-through audit trail from a headline number down to its source. It shows how a number was
built; it does not decide what the number is. It only displays figures that other modules already calculate. It is
also the structured JSON an AI explainer will need ("why is this number what it is"), so one build serves both.
Not a throwaway debug page. Route and page code: see Section 6.

===============================================================================
2. RULES
===============================================================================
- Definition of done (conventions 2026-10-16): a new calculated figure is not done until it has a trace node and the
  node matches the screen. Display-only figures included; input-field coaching excluded. Add "trace node exists and
  matches the screen" to every batch that adds a figure.
- A node resolves its value from the same output-contract field the real page reads. It never recalculates.
- Boundary nodes: where a figure is built across many rows by an aggregation (Rate Builder recovery rows, the
  Business Outcome real-capacity and assumed-capacity cascades), model ONE boundary node traced via the hook's known
  output and do not atomise every intermediate step. State that in formula_text.
- Do not draw an edge that implies a shared derivation that does not exist. (Session 13: View B materials was wired
  to View A's materials net profit; the live test showed the values differ, 0.33 vs 0. The fix added
  business_outcome.materials.view_b_net_profit.)
- Shared values (an overhead pool feeding several groups, an asset in several groups, staff split across groups) are
  shown as shared nodes with several consumers, not copied into each branch.
- implementation_status: live_verified_field = direct field confirmed by reading the hook or selector that produces it.
  live_traced_via_hook = hook wiring confirmed, deeper arithmetic not re-derived.
- A null input must show as blank, never 0 (see finding T-3).

===============================================================================
3. NODE CONTRACT (as built)
===============================================================================
Fields: node_id, display_label, module_name, is_root_input, value_format, formula_text, brief_reference,
last_verified_against, source_file, implementation_status, inputs[] (node_ids), resolve(live) -> value.
Ids are dotted: <module>.<thing>.<field>. Dynamic ids carry a row id, for example assets.<asset_id>.total_asset_cost_annual.
The live-values bag passed to resolve() is assembled in calculationTraceLiveValues.js.
Open: node shape is not final. Every node is to be stored in the database (stress-test brief Q-6), and the explainer
may need result_interpretation text per node (AI brief D-1). Decide the shape before the database step (R6).
