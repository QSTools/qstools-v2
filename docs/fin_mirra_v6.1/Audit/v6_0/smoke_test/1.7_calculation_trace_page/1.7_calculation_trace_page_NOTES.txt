WHAT WAS DONE
Rebuilt lib/calculation-trace/ and app/calculation-trace/page.jsx from a
static, hand-authored pilot map (representative-proof-only, not live data)
into a live tool that resolves real values from the same output_contracts
the actual app pages read. Root scope for this pass: Business Summary,
Cost Summary, Labour, Assets, General Overheads, Revenue/COGS - the module
set already mapped in the pre-existing pilot data. Rate Builder, Business
Outcome, and Business Modelling tracing are NOT yet built into this graph -
that is the next incremental step, per the future-build brief's own
"build incrementally, not as one push" instruction.

ARCHITECTURE
- Option A (self-contained): the trace page mounts its own
  useModelReadiness() / useRevenueCogs() / useCostSummary() chain and calls
  calculateBusinessSummary() directly - the same composition
  useBusinessSummary.js uses internally. No shipped hook was modified.
- Nodes carry an inputs[] array (feeding node IDs) and a resolve(liveValues)
  function; edges are generated from inputs[] rather than hand-duplicated
  in a separate file.
- Dynamic nodes (individual assets, individual staff, individual overhead
  pools) are built at render time from live data, not hardcoded - this is
  what makes the shared-pool / shared-asset "web, not tree" case (brief
  section 3) work: a pool node has no inputs of its own, and every asset
  or line drawing on it lists the pool's node_id in ITS inputs, so the
  page can show both "fed by" and "also feeds" for any shared node.

DRIFT FOUND VS THE OLD v4.0/v5.0 LINEAGE MAP
1. Assets - the old itemized ownership-cost model (7 separate cost fields:
   ownership, finance interest, lease, depreciation, insurance,
   registration, other) does not exist in live code. Real code
   (assetCalculations.js) computes total_asset_cost_annual as
   asset_interest_annual + running_cost_annual, where running_cost_annual
   is currently a hardcoded 0 - no input feeds it.
2. What replaced the itemized model: insurance, registration, fuel,
   vehicle maintenance etc. are now entered on the General Overheads page,
   auto-tagged into a shared "pool" (asset_overhead_pools), then each
   asset is assigned a slice of the relevant pool
   (allocated_asset_overhead_cost_annual). An asset's true total recovery
   cost is total_asset_cost_annual + allocated_asset_overhead_cost_annual
   = asset_recovery_cost_annual. Confirmed with the owner this is the
   correct/expected mechanism, not a regression.
3. General Overheads - the old "gross_general_overheads_benchmark minus
   asset_finance_interest_excluded_amount" single top-level subtraction
   model does not exist. Real code (generalOverheadCalculations.js)
   reduces each flagged row individually (active_amount), then sums.
