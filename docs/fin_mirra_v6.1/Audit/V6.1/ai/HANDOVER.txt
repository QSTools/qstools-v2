3. WHAT THE CODE READ SHOWED (read-only, no change)
 - A staff member is non-productive when Labour marks labour_class "support" (costAllocationLabourAdapter.js). Cost Allocation keeps a productive labour pool and a non-productive labour pool.
 - Staff cost reaches a working group ONLY through a labour_group_assignment (staff type, group, percent) stored in Cost Allocation's real key. A non-productive person with no assignment is NOT spread: the cost sits in unassigned_non_productive_labour_cost. Only SUPPORT ASSETS get an automatic even spread (F-4, costAllocationUnassignedAssetSpread.js, red warning). Neither mechanism weights by recovery hours; the overhead pool does. So an unplaced scratch office hire would silently drop out: that is why decision c routes it through the overhead pool.
 - Staff rows in useLabour carry staff_id, staff_type_id, labour_class, is_productive, contributes_to_recovery_hours, annual_labour_cost, productive_hours_annual. Asset rows (useAssets) carry asset_id, asset_type ("support" = non-productive), asset_recovery_cost_annual, utilisation_hours_annual, asset_overhead_pool_assignments.
 - NOT checked: the exact cost fields every consumer expects on a scratch staff or asset row; Rate Builder behaviour for a staff type with no saved charge-out rate (expected: floors only, no error); the unassigned-asset-spread file was not staged and not read; the cost allocation hook was read only for the assignment handling.
