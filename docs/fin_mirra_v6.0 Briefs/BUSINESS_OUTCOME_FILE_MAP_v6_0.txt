## 1. The data flow (read this first)

hooks/useBusinessOutcomePerSourceRevenue.js
  (raw calculations, returns per_source_result)
        v
lib/selectors/business-outcome/businessOutcomePerSourceRevenueSelectors.js
  selectBusinessOutcomePerSourceRevenue() - RESHAPES the raw result into per_source
        v
components/business-outcome-truth/BusinessOutcomePerSourceRevenueCard.jsx
  (the main page Card - receives per_source as a prop, renders everything)
        v
  passes pieces of per_source down as props to sub-components:
  - BusinessOutcomeTruthSituationSummary.jsx (the blurb)
  - BusinessOutcomeViewABComparisonTable.jsx
  - BusinessOutcomeCapacityCoverageGapTable.jsx
  - BusinessOutcomeHealthGauge.jsx
  - BusinessOutcomeHealthGaugeExplainer.jsx (NEW 2026-09-12)
  - RealCapacityLedger, AssumedCapacityLedger, CostBuildUpTable (defined inline in the Card itself)
  - ViewBRealCapacityLedger, ViewBCostBuildUpTable (View B equivalents, also inline in the Card)

**The #1 rule that bites every time:** a new field added to the hook's return object does NOT automatically reach the Card. It must ALSO be added to the selector's return object (selectBusinessOutcomePerSourceRevenue's own return { ... }, near the existing view_b:, capacity_coverage_gap:, health_gauge: lines). Search per_source_result. in that file to see the existing pattern before adding a new one.

A SEPARATE, parallel path exists for the Net Profit build-up table (see
Section 2/3 corrections below) - it does not flow through
BusinessOutcomePerSourceRevenueCard.jsx's own merge functions, it has its own
selector file and its own component, BusinessOutcomeNetProfitBuildUp.jsx.

## 4. The recurring gotchas

**1. The blurb has two separate prop lists.** File: BusinessOutcomeTruthSituationSummary.jsx. A new prop must be added in three places: the Card's JSX call, the wrapper's destructuring, and the wrapper's forwarding call into build_situation_summary. Miss the middle one and the paragraph silently doesn't render.

**2. The selector explicitly lists every field it returns.** File: businessOutcomePerSourceRevenueSelectors.js, inside selectBusinessOutcomePerSourceRevenue(). A new field on the hook's raw return object will NOT reach the Card unless also added here.

**3. Links into "How the Numbers Are Calculated" need the pre-toggle.** Any ScrollToSectionLink or scroll_to_section() call pointing there needs pre_toggle_labels: ["Show breakdown"] in addition to ancestor_ids.

**4. THERE ARE TWO true_cost SOURCES - FIXED 8b (2026-09-23, BO-1). Originally confirmed 2026-09-18, cost a full session to find.** The selector's group_sources_by_group()/group_true_cost (businessOutcomePerSourceRevenueSelectors.js) sums RAW, per-row true_cost - it was NEVER touched by the non-productive cost injection (that injection only ever lived inside apply_real_capacity/apply_real_capacity_v2's own ephemeral `groups` calculation, never written back to the original row objects). The CORRECT, injected figure lives in real_capacity.group_real_capacity[].true_cost (View A) and view_b.real_capacity.group_real_capacity[].true_cost (View B). FIXED in: CostBuildUpTable, merge_view_b_groups (both call sites), and - 8b - merge_groups_by_id_real_capacity (both staff and asset rows) and businessOutcomeNetProfitBuildUpSelectors.js (the Revenue / Net Profit table). The mechanism used for the 8b fix: distribute_non_productive_cost() now stamps row.non_productive_share directly onto each row in both cascades, so any consumer can add it to the row's own true_cost without needing to cross-reference group_real_capacity separately. Grep both group_true_cost and entry.total_cost before trusting any NEW or unfamiliar cost display that isn't listed as fixed here - this class of bug can still recur in a component not yet built.

**5. SEAT HOURS vs COVERED HOURS (v6.0 BO-6, 2026-09-23).** group.group_recovery_hours from Cost Allocation is the asset's SEAT hours. Business Outcome revenue must use get_group_covered_hours(group) instead - min(seat hours, assigned labour hours) for asset-driven units. group_real_capacity[].group_recovery_hours is ALREADY covered hours. Any new revenue or lever code that multiplies a rate by the raw Cost Allocation hours re-introduces revenue for hours nobody works. The older "seat-hours" comment above build_labour_sources is superseded where labour is short.

**6. TWO overhead-per-hour BASES USED TO EXIST FOR LABOUR - FIXED 8b (F7/BO-2, 2026-09-23).** Rate Builder's rate_builder_labour_recovery_rows puts 100% of a group's overhead on labour regardless of assets (RB-1, still true INSIDE Rate Builder itself - this was never a Rate Builder bug, just a different, valid basis for a different purpose). Business Outcome's own split_group_overhead divides a group's overhead between labour and asset by cost share. The Labour Recovery card used to read the Rate Builder basis while every other figure on the page used Business Outcome's own split - they agreed only for asset-less groups. FIXED: useBusinessOutcomeLabourRecovery.js now builds its overhead map from per_source.labour_groups directly (hours-weighted average per staff type across every group they appear in), so the whole page is on one consistent basis. Watch for this pattern recurring if a new display ever reads rate_builder_labour_recovery_rows directly for a per-staff-type overhead figure instead of going through per_source.

## 5. Field-name traps

- per_source.labour_groups[] / asset_groups[] use .group_modelled_revenue / .group_true_cost, NOT .modelled_revenue/.total_cost.
- per_source.labour_groups[].staff[] rows (and asset_groups[].assets[] rows) carry .non_productive_share as of 8b (BO-1 Part B) - the row's own slice of its working unit's non-productive cost, stamped by distribute_non_productive_cost() in both cascades. A row's full true cost incl. support share = (row.true_cost ?? 0) + (row.non_productive_share ?? 0).
- per_source.materials uses .revenue for View A's residual figure, NOT .modelled_revenue.
- per_source.view_b.labour_sources[] / .asset_sources[] / .materials DO use .modelled_revenue directly.
- real_capacity.group_real_capacity[] has both naive_net_profit and final_net_profit - pick deliberately. Also has true_cost (the CORRECT, non-productive-cost-injected figure - see gotcha #4 above) and non_productive_cost (added 2026-09-17/18) - both present on View A's array from the start, both added to View B's array only on 2026-09-18. modelled_revenue was ALSO missing from View B's array until 2026-09-18 (second pass, same day) - check any new consumer of this array works from BOTH views, since View A always had every field View B has only recently caught up to.
- per_source.view_b_headline_real_capacity - Same shape as headline_real_capacity, built for Business Modelling's real-engine rerun specifically (View B is the only cascade where materials has genuinely independent, lever-movable economics). Built inline in selectBusinessOutcomePerSourceRevenue(), deliberately NOT reusing merge_view_b_groups (a UI-layer function in the Card component - a selector importing from a UI component would be backwards). As of 8b (BO-11/F8), this object's net_profit includes any View B surplus (unexplained_revenue) - see gotcha entries above.
- view_b_headline_real_capacity.unexplained_revenue - NEW 8b (BO-11/F8). Real revenue above what View B's modelled sources explain, added into net_profit; 0 whenever real revenue does not exceed modelled. NOT yet broken out as its own row in the visible breakdown list (BO-12, logged, not built).
- Assumed Capacity mode's net_profit (implied_net_profit / assumed_net_profit, via apply_revenue_ceiling/apply_revenue_ceiling_v2) is a SEPARATE mechanism from the real-capacity cascade, never touched by the non-productive injection - as of 2026-09-18, CostBuildUpTable and merge_view_b_groups both now recompute it directly as (assumed revenue - corrected true_cost) rather than trusting that field, for exactly this reason.
- Per-source direct/overhead cost IS tracked separately: direct_cost, overhead_share, summed to true_cost - confirmed in useBusinessOutcomePerSourceRevenue.js and carried through the selector as group_true_cost, group_overhead_share.
- capacity_coverage_gap[].gap_type "revenue_at_risk" - key name kept, but since v6.0 BO-6 it means revenue NOT earned (already excluded from modelled revenue), valued at asset blended rate + assigned labour weighted charge rate. UI label: "Revenue not earned".
- minimum_recoverable_rate_per_hour on staff / asset rows is the GROUP's rate (Cost Allocation group cost / group hours, excludes non-productive cost) - by design (v6.0 BO-3), not the person's own. Label "Group min rate" as of 8b (F3).
- minimum_recoverable_markup_percent (View B materials) is the ACHIEVED markup, computed post-cascade in apply_real_capacity_v2 - resolved 8b (BO-9), labelled "Achieved markup" on the card. Not a stored/set minimum despite the field name.
- Always grep for an existing working consumer of a field before writing new code that reads it.
